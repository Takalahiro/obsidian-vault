# elec.ino 程序分析

这不是一辆“看见开口就拐”的小车。`elec.ino` 把一条迷宫跑拆成四层，每一层都有现成的名字：

| 层   | 名字                                      | 代码落点                                  |
| --- | --------------------------------------- | ------------------------------------- |
| 感知  | 载波解调红外 + 滞回分类 + 7 帧多数表决                 | `irRead` / `hasWall` / `scanWindow`   |
| 控制  | 差速底盘上的 P 控制，误差先过一阶 IIR，再套死区和 slew limit | `driveCorrected`                      |
| 运动学 | 开环航位推算。脉宽乘时间就是位移，转角没有陀螺闭环               | `turnTo` / `T_CELL` / `accountMotion` |
| 决策  | 左孩子优先的深度优先搜索。路口是顶点，走廊是边，栈就是探索树          | `serviceJunction`                     |

普通模式就是这棵 DFS，拆开是五步，每一步都对应一个函数：

1. 走廊里不搜索。`driveCorrected()` 只负责把车留在两墙中间，`phase` 这台 Moore 机决定现在是全速、在接近前墙，还是在把车开到路口中心。
2. 对中时间到了，或者鼻子已经贴墙，才调用 `serviceJunction()`。这一次调用才是 DFS 的一次转移。
3. 如果这条腿是去探索的（`travelKind == 0`），先 push。新顶点记下四个绝对方向里哪些是通的，来路立刻标成已访问，避免把来路当成新路再走一遍。
4. 出边顺序写死为左转、直行、右转。第一条“现在是开的、记录里也是开的、还没走过、又不是父边”的方向被选中，车转过去，这条新边记成未完成的探索。
5. 三条出边都没有时 pop。车沿父边开回去。回到上一个顶点时不 push，而是用 `openMask ^ 现在的扫描` 做签名核对。除了正后方那一位，其余方向必须和当初记下的一样，否则故障 8，搜索停在原地。

上一张地图把这五步整个拆掉，换成一条写死的相对动作序列 `{右, 右, 右, 掉头, 左, 左, 左}`。走完 7 步之后不再找顶点，最后一段用第一段去程的时间做开环返航。START 1 的 120 ms / 180 ms 也不改这五步的选边顺序，只改第 2 步里“开口出现之后还要再开多久”。

车上没有编码器，没有陀螺，没有格子地图。航向是软件罗盘，只在 `turnTo()` 把阻塞旋转跑完之后更新。打滑 10 度，`heading` 不会知道。从 START 1 出发、车头朝图片左边时：

| `heading` | 图上的方向 |
|---|---|
| 0 | 左 |
| 1 | 上 |
| 2 | 右 |
| 3 | 下 |

四个方向压进一个 nibble，也就是一个字节的低 4 位。`1 << heading` 把航向变成这一位上的 1。`openMask ^ observedMask` 把“当初的开口”和“现在的开口”不同的那些位标成 1。`(heading + 3) % 4` 是左转，因为在模 4 的圆上，加 3 和减 1 是同一步。

后面每一节先给这层起名字，再把名字拆回代码：感知看哪几次采样算一票，控制看误差怎么变成左右脉宽，航位推算看哪一段毫秒被当成一格，DFS 看栈在哪一行 push、在哪一行 pop。名字只是索引，每一节下面的步骤才是程序真正在做的事。

## 读代码前先有的几块知识

后面每一段都会用到这些东西。每个知识点都先写中文，再写一段英文，专业名称用「中文 / English」标出来。读到后面的函数时，可以回到这里对照。

### 知识点：超级循环 / Super Loop，以及阻塞 / Blocking

**中文**

Arduino 程序没有你自己写的 `main`。上电后底层先调用一次 `setup()`，然后永远反复调用 `loop()`。这种结构叫超级循环（super loop）：一个大循环轮流做“读传感器、算、写执行器”。没有操作系统帮你同时跑两个任务，所以每个函数都得自己返回，下一圈才能继续。

这份程序里：

- `setup()`：配置引脚、停车、把起点记成一个虚拟路口、读一次传感器、开始往前开。
- `loop()`：读传感器、更新状态、决定这一帧是继续开、减速、转弯，还是已经结束只亮灯。

`loop()` 每转一圈就返回。舵机脉宽会一直保持到下一次 `writeMicroseconds()`。这一帧决定往前开之后，下一帧读传感器时车仍然在动。主循环是在轮询（polling）传感器：程序主动一次次去读，接收头不会自己打断 CPU。

`turnTo()` 是例外。它里面有 `while` 和 `delay(1)`，转完才返回。这段时间 `loop()` 不会再跑，前方红外也不会扫。这种写法叫阻塞（blocking）：当前这件事独占处理器，其他逻辑都等着。`delay()` 本身就是阻塞等待。与之相对，阶段 1 和阶段 2 的“再开 1110 ms”是非阻塞（non-blocking）的：每圈只看 `millis()` 到了没有，到了就转移，没到就返回，下一圈还能读墙。

**English**

A super loop is the usual Arduino structure: `setup()` runs once, then `loop()` repeats forever. There is no operating system switching tasks, so each function must return before the next sensor read can happen. Polling means the program asks the sensors on every pass; the infrared receiver does not interrupt the CPU. `turnTo()` is blocking: a `while` plus `delay()` holds the processor until the spin finishes, so the front sensor is not read during the turn. The timed approaches in phase 1 and phase 2 are non-blocking: each pass only compares `millis()` with a deadline and then returns.

### 知识点：舵机信号、脉宽调制 / PWM，以及连续旋转舵机 / Continuous-Rotation Servo

**中文**

脉宽调制（pulse-width modulation，PWM）用一串开关脉冲传递信息。电机调速里，人们常说占空比（duty cycle）：一个周期里高电平所占的百分比越高，平均电压越高，普通直流电机越快。

航模舵机（hobby servo）用的是另一种约定，信息在脉冲宽度（pulse width），单位是微秒（microsecond，µs）。标准角度舵机（positional servo）大约每 20 ms 收一个脉冲，也就是 50 Hz。脉冲宽约 1000 µs 在转角一端，1500 µs 在机械中位，2000 µs 在另一端。`Servo.writeMicroseconds(1490)` 的意思是：把脉冲宽度设成 1490 µs。周期仍由舵机库维持在大约 20 ms，程序不用自己算占空比。

连续旋转舵机（continuous-rotation servo）插头和脉冲格式相同，内部把“目标角度”换成了“目标转速”：

- 脉冲在中位附近：停。这个中位叫空脉宽或机械中点（neutral pulse）。
- 比中点宽：朝一个方向转，偏得越多越快。
- 比中点窄：朝另一个方向转。

每一只成品的真正中点都有偏差，所以要做微调（trim）。这里两边的停止脉宽都标成 1490，而不是资料上常见的 1500。左右轮镜像安装，前进对应的脉宽方向相反：左轮前进是 1548（比停止值大 58 µs），右轮前进是 1438（比停止值小 52 µs）。

原地右转时两个脉宽都写到 1570 附近：左轮更加前进，右轮的脉宽高于自己的前进区，变成后退。两侧速度方向相反，车绕垂直轴转动，这个转动叫偏航（yaw）。左转则两个脉宽都降到 1430 附近。

**English**

Pulse-width modulation sends information by switching a signal on and off. For an ordinary DC motor, the duty cycle is the percentage of each period spent high, and a higher duty cycle means a higher average voltage. A hobby servo uses a different convention: the information is the pulse width in microseconds. A positional servo expects a pulse about every 20 ms (50 Hz); roughly 1000 µs, 1500 µs, and 2000 µs are the two ends and the center of its travel. `writeMicroseconds(1490)` sets that width. The library keeps the 20 ms frame, so the sketch does not compute a duty cycle.

A continuous-rotation servo accepts the same pulses, but the neutral pulse means stop and any offset means speed and direction. The stored 1490 µs values are a trim of the mechanical neutral, which is not exactly 1500 µs on a real unit. The wheels are mounted as mirrors, so the left wheel drives forward above neutral and the right wheel drives forward below neutral. A right spin drives the left wheel forward and the right wheel backward, producing yaw, a rotation about the vertical axis.

### 知识点：差速驱动 / Differential Drive

**中文**

两个驱动轮各走各的，靠转速差转向，这叫差速驱动（differential drive）。常见小车还有一个万向轮承担重量，转向力来自这两个驱动轮。

- 两轮前进速度一样：直线。
- 一侧变快、另一侧变慢：车朝慢的那一侧弯。弯的大小由转速差决定。
- 一侧前进、一侧后退，而且快慢接近：原地转，旋转中心大约在两轮中间。

`driveCorrected()` 里的 `correction` 同时加到左右两个脉宽上。右轮的前进方向和“脉宽变大”是反的，所以正的 `correction` 让左轮更快、右轮更慢，车向右修。负的修正向左修。后面计算误差（error）的正负，就是按这个关系配的。设定值（setpoint）是“左右票数都接近 7”；测到的票数是过程量（process variable）；两者的差就是误差。

**English**

A differential-drive robot steers by giving its two driven wheels different speeds. Equal forward speeds go straight. A faster left wheel and a slower right wheel yaw the robot to the right. Opposite wheel directions turn it in place about a point between the wheels. Because the right wheel is mirrored, adding the same `correction` to both pulse widths speeds up the left wheel and slows the right wheel when the correction is positive. The setpoint is the desired wall reading, about 7 votes; the measured votes are the process variable; their difference is the error.

### 知识点：开环控制 / Open-Loop Control，闭环控制 / Closed-Loop Control，航位推算 / Dead Reckoning

**中文**

闭环控制（closed-loop control）会测量结果，再拿结果和目标比较。编码器（encoder）装在轮子上，能数实际转过的角度，控制器就可以把“命令开 10 cm”收成“真的开到 10 cm”。陀螺仪（gyroscope）测量角速度，积分之后得到转过的角度。两者都属于反馈（feedback）。

这份程序的路程和转角是开环控制（open-loop control）：发出“这个脉宽维持 615 ms”，然后相信车转了大约 90°。它不读真实角度，也不读真实位移。用速度乘时间去估计位置，叫航位推算（dead reckoning）。这里的“速度”还是假定的：某个脉宽被当成某个固定速度，1480 ms 被当成一个格子。

电池电压、地面摩擦、车是否蹭墙，都会让真实速度变化，航位推算的误差会随时间积累，这叫漂移（drift）。所以 `T_CELL`、转弯毫秒、路口居中毫秒都是标定（calibration）：在这块场地、这块电池上试出来的数。`J1_EARLY_MS` 和 `J3_LATE_MS` 注释写明是盲估，意思是还没有做这次标定。速度一变，这两个补偿对应的厘米数就变了。

直行纠偏是一条局部闭环：左右红外被当成反馈，把车往走廊中间推。它纠正的是横向位置，不纠正“这一格一共开了多少毫秒”。沿走廊走的时间仍然是开环的。

**English**

Closed-loop control measures the result and compares it with the target. A wheel encoder counts actual rotation; a gyroscope measures angular rate, which can be integrated into an angle. Both are feedback. Distance and heading in this sketch are open-loop: a pulse width is held for a fixed time, and the program then believes the robot has moved one cell or turned 90°. Estimating pose from assumed speed and elapsed time is dead reckoning. Battery voltage, floor friction, and wall contact change the real speed, so the estimate drifts. The millisecond constants are a calibration for this robot and this floor. The blind junction trims have not had that calibration. Wall correction is a local closed loop in the sideways direction only; travel time along the corridor stays open-loop.

### 知识点：`millis()`、无符号整数 / Unsigned Integer，以及溢出 / Overflow

**中文**

`millis()` 返回上电后经过的毫秒，类型是 `unsigned long`，32 位无符号整数（unsigned 32-bit integer）。无符号表示没有负数，范围是 0 到 4,294,967,295。大约 49.7 天后这个计数器回到 0，叫溢出（overflow）或回绕（wraparound）。

计时的标准写法是记下开始时刻，再用现在减去开始：

```text
if (millis() - phaseStartedAt >= centerTime) { ... }
```

无符号减法本身按模 2^32 计算。只要间隔短于大约 49 天，即使计数器中途回绕，差值仍然是真实经过的毫秒。程序里所有“开了多久”都是这个形式。

`delay(1)` 把 CPU 停住大约 1 毫秒。`delayMicroseconds(700)` 停住 700 微秒。红外采样大量使用后者，所以主循环一帧并不短：一个传感器 5 个频率、每个 3 次，一次采样大约 1 毫秒，一个传感器大约 15 毫秒，左前右一起大约 40 到 50 毫秒。车在这一帧里继续按上一帧的脉宽走。主循环因此先读前方，一发现贴墙就马上 `stopRobot()`，然后才读左右。

无符号下溢（underflow）是同一个圆环的另一面：无符号数减去一个更大的数，结果不是负数，而是绕到 40 亿附近。`subtractWithoutUnderflow()` 和返程时间里先转成 `long` 再相加，都是为了避开这件事。`long` 是有符号整数（signed integer），可以表示负数。

**English**

`millis()` returns milliseconds since boot as an unsigned 32-bit integer. It has no negative values and wraps back to 0 after about 49.7 days. That wrap is an overflow. Unsigned subtraction is modulo 2^32, so `now - start` is still the real elapsed time across one wrap, provided the interval is shorter than the full range. `delay()` and `delayMicroseconds()` block the CPU. One infrared sensor takes about 15 ms, and three sensors take about 40–50 ms, during which the robot keeps the previous servo command. That is why the front sensor is read and acted on before the side sensors. Unsigned underflow is the same circle: subtracting a larger unsigned value jumps to a number near 2^32 instead of becoming negative. The code converts to a signed `long` or uses an explicit check before subtracting.

### 知识点：调制 / Modulation、载波 / Carrier、解调 / Demodulation，以及低电平有效 / Active-Low

**中文**

红外（infrared，IR）是可见光红端以外的一段光。迷宫车上的发射管发出人眼看不见的近红外，接收头负责把“有没有这束光反射回来”变成电平。

太阳光和灯光里也有红外。接收头如果只看亮度，会被环境光淹没。所以发射端先做调制（modulation）：用一个高频方波（square wave）去开关红外灯。这个高频叫载波（carrier）。`tone(tx, 38000)` 让发射脚输出 38 kHz 方波。38 kHz 的周期是 1/38000 ≈ 26.3 µs，`delayMicroseconds(700)` 大约是 27 个载波周期，组成一次猝发（burst）。然后 `noTone()` 关掉，再空 250 µs。许多一体接收头要看到足够长的猝发才承认，猝发之间还要留空，避免内部自动增益（automatic gain control，AGC）被持续强光压低灵敏度。

接收头内部做解调（demodulation）：确认这是它要的载波之后，把载波去掉，输出一个开关量。常见一体化接收头是低电平有效（active-low）：看到合法猝发时，输出脚变成低电平。代码里 `digitalRead(rx) == LOW` 因此表示“这次收到了反射”。高电平表示这次没收到。

墙越近，反射越强，能通过接收头门槛的频率和采样次数越多。`bands` 和 `votes` 是距离的代理量（proxy）：和距离有关，但单位不是毫米，也不能换成一把标定过的尺子。近墙时两个数都大，开口时两个数都接近 0。

这里的 `TX` / `RX` 是发射（transmitter）和接收（receiver）。同一对缩写在串口上表示发送线和接收线，这份程序里的 10/11、6/7、2/3 脚不是串口。

**English**

Infrared is light just beyond visible red. The emitter produces a near-infrared beam, and the receiver turns a reflection into a logic level. Ambient light also contains infrared, so the beam is modulated: a square-wave carrier, here 38 kHz from `tone()`, switches the LED on and off. The period of 38 kHz is about 26.3 µs, so a 700 µs wait is a burst of about 27 cycles, followed by a 250 µs gap. Many demodulating receivers need a minimum burst and a gap so their automatic gain control is not driven down by a continuous signal. Demodulation removes the carrier and leaves a logic level. These modules are commonly active-low: the pin reads `LOW` when a valid burst is detected. `bands` and `votes` are a proxy for distance, not a calibrated millimetre reading. In this sketch, TX and RX mean the infrared transmitter and receiver, not a UART serial port.

### 知识点：阈值 / Threshold、滞回 / Hysteresis、消抖 / Debounce、多数表决 / Majority Vote

**中文**

阈值（threshold）是一个分界数。`bands >= 3` 就叫前墙，3 就是阈值。

如果“大于 2 是墙、小于 2 是开口”，读数在 2 附近抖一下，结论会每帧翻转，这叫抖动（chatter）。滞回（hysteresis）用两个不同的阈值：往上越过较高的线才算墙，往下跌到很低才算开口，中间留出不确定区。电子电路里的施密特触发器（Schmitt trigger）做的是同一件事。这份程序的侧向就是这样：`hasWall` 要 `bands >= 2` 或 `votes >= 3`，`isOpen` 要 `bands == 0` 且 `votes <= 1`，中间的读数返回 −1，不拿来做路口决定。

消抖（debounce）原来指机械开关弹跳时，要等电平稳定一段时间再承认状态变化。这里的连续 3 帧开口、连续 3 帧有墙，就是对传感器抖动做消抖。单帧噪声不改变行为。

多数表决（majority vote）是 N 次里至少 K 次同意才采纳。一个频率 3 次采样里至少 2 次成功，这个频率才算一个 band。7 帧窗口里侧向至少 5 帧一致、前向至少 6 帧一致，才输出墙或开口。窗口没满，或者两边票数都不够，结果保持 −1。−1 在这里是哨兵值（sentinel）：它落在合法结论 0 和 1 之外，专门表示“还不知道”。

**English**

A threshold is the number a measurement is compared with. Chatter is a decision flipping every sample because the reading sits on that line. Hysteresis uses two thresholds, one to enter a state and another to leave it, leaving a gap where the result stays unknown. A Schmitt trigger is the electronic version of that gap. Debounce means waiting until a condition has held for several samples before accepting it; the 3-frame open and wall counts do that. A majority vote accepts a result only after at least K of N samples agree: 2 of 3 hits make one band, and 5 of 7 or 6 of 7 frames make a side or front decision. The value −1 is a sentinel, a reserved code outside the real results 0 and 1, meaning unknown.

### 知识点：比特掩码 / Bit Mask，以及位运算 / Bitwise Operations

**中文**

一个 `uint8_t` 有 8 个二进制位（bit）。8 位一组常叫一个字节（byte）。低 4 位单独叫一个半字节（nibble）。这份程序只用最低 4 位，一位对应一个绝对方向：

| 方向 | 运算 | 二进制 |
|---|---|---|
| 0 图左 | `1 << 0` | `00000001` |
| 1 图上 | `1 << 1` | `00000010` |
| 2 图右 | `1 << 2` | `00000100` |
| 3 图下 | `1 << 3` | `00001000` |

`1 << n` 是左移（left shift）：把 1 往高位挪 n 格。掩码（mask）是一个用来挑选某些位的数。路口里反复出现这些位运算（bitwise operations）：

- 按位或（bitwise OR）`mask | bit`：只要有一边是 1，结果就是 1。用来把某一位置成 1，表示“这个方向也通”或“这个方向走过了”。原来为 1 的位还保持 1。
- 按位与（bitwise AND）`mask & bit`：两边都是 1，结果才是 1。用来测试某一位。结果非 0 就是开着或走过。
- 按位异或（bitwise XOR）`mask ^ other`：两位不同才是 1。两位相同变成 0。用来标出“当初的开口”和“现在的开口”哪些方向不一致。
- 按位非（bitwise NOT）`~bit` 再和 `0x0F` 相与：`~` 把 0 和 1 对调。`0x0F` 是低 4 位全 1 的掩码，用来把高 4 位清掉，只在半字节里排除某一个方向。

例如车头朝图左（`heading = 0`），左开、前墙、右开。后方没有传感器，程序把来路一律当成通的：

- 左是方向 3，右是方向 1，后是方向 2，前是墙所以不置位。
- 掩码 = 方向 3、1、2 做按位或 = `00001110`。

**English**

A `uint8_t` holds one byte, eight bits. The low four bits are a nibble, and this program uses one bit per absolute direction. `1 << n` is a left shift that places a 1 in bit n. A mask selects bits. Bitwise OR sets a bit and leaves the others unchanged. Bitwise AND tests a bit. Bitwise XOR marks bits that differ, which is how a stored junction is compared with a new scan. Bitwise NOT flips every bit; AND with `0x0F` then keeps only the low nibble so one direction can be excluded from the comparison.

### 知识点：模运算 / Modulo

**中文**

模运算（modulo）取除法的余数。方向排成一个圈：0 → 1 → 2 → 3 → 0，所以加完要对 4 取余。这和钟表对 12 取余是同一类运算，叫模运算，也叫环绕算术（modular arithmetic）。

- `(heading + 1) % 4`：右转 90°。
- `(heading + 2) % 4`：掉头 180°。
- `(heading + 3) % 4`：左转 90°。加 3 和减 1 在模 4 下是同一件事。写成加 3，运算过程中不会出现负数。
- `(target - heading + 4) % 4`：从当前朝向转到目标。余数 0 直行、1 右转、2 掉头、3 左转。前面加 4，是为了相减之后仍然落在非负范围。C++ 里负数取余的符号容易和数学上的模不一致，加 4 把结果拉回 0 到 3。

**English**

Modulo is the remainder after division. The four headings form a circle, so adding a turn and taking the remainder modulo 4 wraps around, the same idea as clock arithmetic. Adding 3 is the same as subtracting 1 modulo 4, and writing it as an add avoids a negative intermediate. `(target - heading + 4) % 4` converts two absolute headings into a relative command: 0 straight, 1 right, 2 U-turn, 3 left. The added 4 keeps the value non-negative before the remainder is taken.

### 知识点：栈 / Stack、深度优先搜索 / Depth-First Search、回溯 / Backtracking

**中文**

栈（stack）是后进先出（last in, first out，LIFO）的一组记录。最后压进去（push）的，最先弹出来（pop）。进迷宫时，每到一个新路口就压栈；这个路口的岔路都试完了，就弹栈，退回更早的那个路口。

沿一条分支走到不能再走，再退回来试下一条，这叫回溯（backtracking）。搜索顺序是深度优先（depth-first search，DFS）：先把一条路走到底，而不是先把同一个路口的所有邻居都看一遍。先看完同一层再往下，那是广度优先（breadth-first search，BFS）。这份程序没有 BFS 用的队列（queue）。

左手定则（left-hand rule），也叫沿墙法（wall follower），是另一种迷宫走法：手一直扶着左侧的墙。它不记路口。在墙壁连成一片、没有独立环岛的迷宫里，它能摸到出口；它不会系统地把每条岔路都试完。这份程序记得每个路口哪些方向开过、哪些已经走过，优先还没走的左转，其次直行，最后右转，全部试完才沿来路退回。退回之后如果那里还有没试的岔路，再走进去。

图论（graph theory）把路口看成顶点（vertex），走廊看成边（edge）。特雷莫算法（Trémaux's algorithm）也用回溯走迷宫，并在地上把每条通道标记为走过一次或两次，因此能处理有环的迷宫。这份程序只在内存栈里记探索树，没有在地上做那种标记。退回时用开口形状做特征签名（signature），核对“栈顶那个路口和现在看到的是不是同一套开口”。车如果从另一条路再次开进同一个物理路口，栈里没有“这个顶点来过”的全局表，程序会把它当成新路口再压一次。栈里存的是路口，不是每一格地面。两路口之间的走廊只靠墙距纠偏开过去。

START 1 那套阶段是按已知地图猜的脚本，猜错了没有第二套定位来发现。

**English**

A stack is last-in, first-out storage: push adds a record and pop removes the newest one. Walking down one branch until it ends, then returning to try the next branch, is backtracking. Doing that in branch-before-sibling order is depth-first search. Breadth-first search would use a queue and finish every neighbor at the current junction before going deeper; this program has no such queue. The left-hand rule, or wall following, keeps one hand on a wall and does not remember junctions. Trémaux's algorithm also backtracks, but it marks each passage on the ground so a maze with loops is still explored once. This sketch stores only the exploration tree in a memory stack. A signature of open directions is checked when returning along that same path. A physical loop that re-enters a junction by another corridor is pushed again, because there is no global set of visited vertices. The stack stores junctions, not every floor cell.

### 知识点：有限状态机 / Finite State Machine

**中文**

有限状态机（finite state machine，FSM）有一份有限的状态表。任意时刻只处在一个状态里。输入和时间满足某个转移条件（transition），就进入另一个状态。处在某个状态时，允许的行为是确定的。

`phase` 就是这样一台机器：

| 值 | 名字 | 这一帧在干什么 |
|---|---|---|
| 0 | 正常行驶 | 全速纠偏，同时等前墙或新的侧开口 |
| 1 | 前墙接近 | 已经看到前墙，再慢速开大约 1.2 个格子 |
| 2 | 侧开口居中 | 已经看到侧开口，再慢速开到预计的路口中心 |

每一帧先看当前状态，只处理这个状态的条件，处理完就 `return`。读 `loop()` 时先看 `phase` 等于几。几个 `if` 不会在同一帧里同时生效。

从“输出主要由当前状态决定”这个角度看，它接近摩尔机（Moore machine）：这一帧开 85% 还是 100%，主要由 `phase` 决定。转移条件来自传感器和时间。START 1 的 `start1RouteStage` 是另一台更小的状态机，而且只向前转移，没有退回上一阶段的边。

**English**

A finite state machine has a fixed list of states, is in exactly one state at a time, and moves along a transition when an input condition is true. `phase` is that machine: normal driving, front-wall approach, or side-opening centering. Each pass of `loop()` handles the current state and returns, so the later `if` statements do not also run. The speed command depends mainly on the current state, which is the Moore-machine pattern. `start1RouteStage` is a second, smaller machine whose transitions only move forward.

## 程序实际怎么转起来

超级循环的一帧只做三件事，而且顺序不能换。先采样，因为决策要用这一帧的红外。再推进 Moore 机，因为 `phase` 决定这一帧是继续开还是已经到了该搜索的时刻。只有对中完成或贴墙时才进入 DFS。`setup()` 结束时车已经在以 85% 的速度往前开，Moore 机停在阶段 0。之后每一圈 `loop()` 按下面的顺序走，命中一条就 `return`，所以同一帧不会既对中又全速直行：

1. `halted` 为真：轮子保持停，按成功或故障码亮灯，本圈结束。
2. 旧地图模式并且 7 次转向已经走完：继续开，开到返程时间就成功结束。
3. 先读前方。贴墙就立刻停车。
4. 再读左右，把这一帧放进 7 帧窗口，更新侧边开口计数。
5. 如果贴墙：3 号补偿还没开完就报故障 13，否则把这次停车当成“已经到了前墙路口”。
6. 否则按状态机：
   - 已经在阶段 2：时间到了就路口决策。
   - 出现新的侧开口：进入阶段 2。
   - 已经在阶段 1：时间到了就路口决策；前方又变开口就把阶段退回 0。
   - 这一帧前方 `bands >= 3`：进入阶段 1。
   - 都没有：100% 速度直行，中间灯亮。

路口决策在 `serviceJunction()`，一次调用就是 DFS 的一步，内部还有先后：

- 探索边到达：先 push，来路写入 `triedMask`，再按左、前、右找未访问出边。
- 退回边到达：先用签名核对栈顶，核对失败就停；核对通过才在这个旧顶点上继续找下一条出边。
- 没有出边：沿 `parentDir` pop。pop 发生在 `depart()` 之前，所以车出发之后，栈顶已经是它要回去的那个更早的顶点。

## 2. 数据结构（第 34–54 行）

### 知识点：结构体 / Struct、定宽整数 / Fixed-Width Integer、引用 / Reference

**中文**

结构体（struct）把几个相关的数绑成一个类型。`Reading` 里是 `bands` 和 `votes`，调用处可以整份传给函数。

参数写成 `const Reading &r` 有两层意思。`&` 是引用（reference）：函数用的是调用者原来的那一份，不把结构体再复制一份。`const` 表示这个函数承诺不修改它。传感器读数只被查看，引用避免了每次调用都复制两个 `int`。

`int8_t` 和 `uint8_t` 是定宽整数（fixed-width integer）。名字里的 8 表示正好 8 位，不随芯片把 `int` 变成 16 位或 32 位而改变。`int8_t` 有符号，范围 −128 到 127，扫描结果才能放进 −1。`uint8_t` 无符号，范围 0 到 255。父方向用 255 表示“没有来路”，因为真实方向只有 0 到 3。这个 255 也是哨兵值。

**English**

A struct groups related fields into one type. A `const Reading &` parameter is a reference, so the function uses the caller's object without copying it, and `const` promises not to modify that object. `int8_t` and `uint8_t` are fixed-width integers: exactly eight bits on every platform. The signed one can hold the sentinel −1; the unsigned one holds 0 through 255, so 255 can mean "no parent" without colliding with headings 0 through 3.

### `Reading`：一次红外测量

`readSensor()` 对一个接收头做 15 次采样：5 个频率，每个频率 3 次。

- `bands`，0 到 5：有几个频率算“这个频率看到墙了”。一个频率 3 次里至少 2 次是 `LOW`，这个频率才算 1 个 band。这是频率内部的多数表决。
- `votes`，0 到 15：15 次采样里 `LOW` 的总次数，不管来自哪个频率。

近墙时两个都高。例如贴到前方时，代码要求 `bands >= 5` 而且 `votes >= 14`，也就是五个频率几乎全部成功、15 票里至少 14 票。开口时 `bands == 0` 且 `votes <= 1`。

两者之间有一片故意留下的不确定区。例如 `bands == 1`、`votes == 2`：既不够格当墙，也不够格当开口。侧向分类会返回 −1。路口决策不使用这种帧。

### `Scan`：把读数收成三路结论

每一路只有三个值：

- `0` 墙
- `1` 开口
- `−1` 窗口没满，或者 7 帧里墙和开口都没达到票数

前向在单帧分类时没有 −1，只要 `bands >= 3` 就是墙，否则就是开。−1 仍然会出现，因为 7 帧还没攒满，或者 7 帧里同意“墙”的不足 6 帧、同意“开”的也不足 6 帧。

### `Junction`：栈里的一个路口

- `openMask`：第一次在这里决策时，四个绝对方向哪些是通的。
- `triedMask`：哪些方向已经出发走过。来路在建档时就放进来，避免再把来路当成新路。
- `parentDir`：进来时的绝对方向。无路可走时退向这里。
- `signatureKnown`：形状能不能拿来核对。起点那个虚拟路口是 `false`，真实路口入栈时写成 `true`。

**中文**

这些引脚都是通用输入输出（general-purpose input/output，GPIO）。`pinMode(pin, OUTPUT)` 把脚设成输出，程序用 `digitalWrite` 决定高电平或低电平。`INPUT` 表示脚只读外部电路给出的电平，程序不主动驱动它。

The infrared emitters are held low while idle. `tone()` then takes one pin and generates the carrier. ## 5. 红外参数（第 112–137 行）

感知前端不是测距仪，是一个 38–42 kHz 的解调投票器。频率表是 38000、39000、40000、41000、42000 Hz。接收头有一个最灵敏的频率，模块之间会差一两万赫兹里的零头；墙的距离也会让边缘频率一会儿能解调、一会儿不能。扫五个频率，既是在找这个模块吃哪一个频率，也是在用“有几个频率还能解调”粗略表示反射强弱。

### 三档判定，中间是空的

侧向用两个函数，条件是“或”和“与”，覆盖范围不一样：

- `hasWall`：`bands >= 2` **或者** `votes >= 3`。稍有反射就倾向认为有墙。
- `isOpen`：`bands <= 0` **并且** `votes <= 1`。几乎完全没有反射才认为是开口。
- 其余：`classifySide()` 返回 −1。

### 知识点：滞回 / Hysteresis 在侧向分类里的具体门槛

**中文**

文首已经说明滞回、抖动和施密特触发器。这里把门槛代进这辆车的数。

侧向如果只用一条线，例如“票数大于 2 算墙、否则算开口”，票数在 2 和 3 之间跳时，车会一帧认为有开口、下一帧认为有墙。`hasWall` 和 `isOpen` 因此留下中间带：

- 升到“墙”：`bands >= 2`，或者 `votes >= 3`。
- 降到“开口”：`bands == 0` 并且 `votes <= 1`。
- `bands == 1` 且 `votes == 2` 这种读数两个函数都是假，`classifySide()` 返回 −1。

从开口认定成墙，反射必须明显变强；从墙认定成开口，反射必须掉到几乎没有。另外，开口事件还要连续 3 帧都落在 `isOpen`，重新允许检测也要连续 3 帧 `hasWall`。那是消抖，和滞回叠在一起用。

**English**

Hysteresis, chatter, and the Schmitt-trigger idea are defined in the opening section. On this robot the rising decision "wall" requires `bands >= 2` or `votes >= 3`. The falling decision "open" requires `bands == 0` and `votes <= 1`. A reading such as `bands == 1` and `votes == 2` is neither, so `classifySide()` returns the sentinel −1. The opening event also waits for 3 frames, and re-arming waits for 3 wall frames. That second rule is debounce layered on top of the two thresholds.

前向分类更简单，也更敢下结论：`bands >= 3` 就是墙，否则就是开。因为前墙会启动“再开 1.2 格”的接近阶段，程序希望早点开始减速，而不是停在不确定里继续全速。真正的“鼻子已经顶到墙”另用 `tooClose`：五个频率全中，且 15 票里至少 14 票。那条路径会立刻停车。

## 6. 纠偏参数（第 139–156 行）

这是整车唯一的闭环，而且只闭环横向：左右墙的反射票数把车往走廊中间推。纵向“开了一格没有”仍靠 `T_CELL = 1480` ms 这种航位推算，控制器不看轮子实际转了多少。

控制律按数据流是五级，每一级都在 `driveCorrected()` 里，缺一级车的手感就会变：

1. 设定值是 7 票。左右都有墙时，误差 = (左票 − 7) − (右票 − 7)。左边反射偏强，误差为正，表示车偏左。
2. 一阶 IIR：`新误差 = 0.2 × 旧误差 + 0.8 × 本帧误差`。单帧跳变只进结果的 80%，避免一票噪声就把方向打满。
3. 死区 ±1。滤波后还在这个带里，目标修正写成 0，车不再为了中线附近的 1 票来回抖。
4. 比例增益 4。目标脉宽修正 = 滤波误差 × 4，再被饱和到大约 ±20 µs。
5. slew limit。就算目标已经是 +19 µs，这一帧也只能比上一帧多 6 µs。方向是爬过去的。

7 不是公式算出来的最优值，是这台底盘停在走廊中线时，侧面接收头大概会给出的票数。换传感器或换墙面，这个工作点要重标。下面的表是这五级对应的常量。

| 常量 | 值 | 作用 |
|---|---|---|
| `FILTER_OLD_WEIGHT` | 0.20 | 滤波器里旧误差保留 20%，新误差占 80% |
| `CORRECTION_GAIN` | 4.0 | 滤波后的误差乘 4，换成微秒 |
| `ERROR_DEADBAND` | 1.0 | 误差在 ±1 以内，修正目标为 0 |
| `ALIGN_LEFT_TARGET` / `ALIGN_RIGHT_TARGET` | 7 / 7 | 左右墙的目标票数 |
| `MAX_CORRECTION` | 22 | 左右都有墙时，修正最大 ±22 微秒 |
| `SINGLE_WALL_MAX_CORRECTION` | 20 | 只有一面墙时 ±20 |
| `CORRECTION_STEP` | 6 | 每一帧修正量相对上一帧最多变化 6 微秒 |

三个变量是纠偏的记忆，换墙或停车时会清掉：

- `filteredError`：平滑后的误差。
- `lastCorrection`：上一帧真正写给电机的修正。
- `correctionWallMask`：上一帧是“左墙、右墙、双墙还是没墙”。组合一变就重新开始平滑，避免把双墙的误差带到单墙阶段。

### 知识点：比例控制 / Proportional Control、指数滑动平均 / EMA、死区 / Deadband、变化率限制 / Slew-Rate Limit

**中文**

误差在 `driveCorrected()` 里按墙的组合来算：

- 左右都有墙：`误差 = (左票 − 7) − (右票 − 7)`。左边反射比设定值强、右边比设定值弱，误差为正，表示车偏左。
- 只有左墙：`误差 = 左票 − 7`。靠左墙太近为正。
- 只有右墙：`误差 = −(右票 − 7)`。靠右墙太近为负。
- 两面都没有：不跟随，误差和修正都清零，按标定速度直开。没有墙就没有横向反馈，这条局部闭环打开。

正误差经过后面的处理会变成正的 `correction`：左轮更快，右轮更慢，车向右离开左墙。负误差向左离开右墙。

四步叠在一起：

1. **指数滑动平均（exponential moving average，EMA），也叫指数平滑。** `新滤波值 = 0.2 × 旧滤波值 + 0.8 × 本帧误差`。旧值权重 0.2 就是 `FILTER_OLD_WEIGHT`。一次突然的跳变只进入结果的 80%，更早的跳变还会按 0.2、0.2²、0.2³ 继续留下尾巴。这种“输出又送回下一次输入”的滤波器叫无限脉冲响应（infinite impulse response，IIR）。它只有一个记忆单元，所以是一阶（first-order）的。作用是低通（low-pass）：慢的偏离能通过，快的票数噪声被削弱。7 帧投票那种“只看固定窗口、算完就丢掉”的做法则更接近有限脉冲响应（finite impulse response，FIR）。
2. **死区（deadband，也叫 dead zone）。** 平滑后的绝对值不超过 1 时，目标修正是 0。车已经基本在设定值上，就不再为 1 票打方向。死区太小，车会绕着中线来回抖，这叫寻迹振荡（hunting）。
3. **比例控制（proportional control）。** 目标修正 = 滤波误差 × 4。4 是比例增益（proportional gain，Kp）。误差越大，命令越大。PID 控制器里的 P 就是这一项。I 是积分（integral）：把过去的误差累加起来，用来消除“永远偏 1 票”的稳态误差（steady-state error），累加过量会积分饱和（integral windup）。D 是微分（derivative）：看误差变得有多快，用来提前减小修正。这份程序没有 I，也没有 D。增益过大时，车会走过头再往回修，也就是超调（overshoot）。
4. **变化率限制（slew-rate limit）。** 就算目标修正一下子想要 +22 µs，这一帧也只能比上一帧多 6 µs。执行器命令的变化被限速，避免脉宽突变让车身抽一下。

限幅（saturation，也叫 clamping）是另一道硬顶：修正先被限制在 ±22 或 ±20，再和“前进偏移减 5”取更小的那个。85% 速度时左轮前进偏移大约是 `58 × 85 / 100 = 49` µs。整数除法（integer division）会把小数直接丢掉，这里 49.3 会变成 49。修正被压在前进偏移以内，加上修正之后轮子仍在前进一侧，纠偏不会把某一侧打成停车或倒转。

**English**

The error is positive when the robot is too close to the left wall: both-wall error is `(left votes − 7) − (right votes − 7)`, left-only error is `left − 7`, and right-only error is the negation of `right − 7`. A positive error becomes a positive `correction`, which speeds the left wheel and slows the mirrored right wheel, so the robot yaws right.

The filter `0.2 × old + 0.8 × new` is an exponential moving average. Because the old output is fed back, it is a first-order infinite-impulse-response low-pass filter: slow drift remains and fast vote noise is reduced. The 7-frame vote is closer to a finite-impulse-response window. The deadband forces the command to 0 while the filtered error is within ±1, which avoids hunting around the setpoint. Multiplying by 4 is proportional control, the P term of a PID controller, and 4 is the proportional gain. The integral term, which would remove steady-state error and can wind up, and the derivative term, which reacts to the rate of change, are absent. The slew-rate limit allows the command to move at most 6 µs per frame. Saturation then clamps it to ±22 µs, or ±20 µs on one wall, and also to less than the forward offset so a correction cannot stop or reverse a wheel. Integer division drops the fractional part, so `58 × 85 / 100` becomes 49 rather than 49.3.

举一个双墙的数。左票 10，右票 4，目标都是 7：

- 原始误差 = (10 − 7) − (4 − 7) = 3 − (−3) = 6。车明显偏左。
- 若上一帧滤波值是 0，本帧滤波值 = 0.8 × 6 = 4.8。
- 4.8 超出死区，目标修正 = 4.8 × 4 = 19 微秒，限制后仍是 19。
- 若上一帧修正是 0，本帧只能变到 +6。车开始向右修，下一帧还可以再加 6，逐步靠近 19。

## 8. 普通模式终点（第 176–190 行）

DFS 搜到根上已经没有出边，在这套实现里是故障 12，灯按 7 下闪，车不停在起点庆祝。成功终止被定义成一条叶边：左右夹墙走得够长，而且决策瞬间左、前、右的签名全是墙。程序把这条边当成迷宫终点，`finishRobot()` 停车，三灯常亮。

它要和普通死胡同分开。普通死胡同也会三面是墙，但长度只有一格左右，DFS 应该 pop 回去继续搜。所以成功条件把“签名是墙”和“这段封闭航位够长”绑在一起。四个条件缺一个就继续当普通顶点处理：

`serviceJunction()` 里四个条件同时成立才 `finishRobot()`：

1. `ENABLE_LONG_DEADEND_FINISH` 开着。
2. 这次出发以来的前进时间至少 2220 ms（1.5 格）。防止刚出门、传感器还看着上一个墙时误结束。
3. 决策用的扫描是左墙、前墙、右墙。
4. `enclosedForwardMs` 至少 4440 ms（3 格）。这段时间必须是左右都有墙的直行时间。

### 封闭走廊计时怎么被打断

`updateSideTracking()` 里：

- 左右同时 `hasWall`：`enclosedNow = true`，主循环里的前进时间会累加到 `enclosedForwardMs`，打断计数清零。
- 否则：只要某一侧已经是明确开口，打断计数加 1。加到 3（`ENCLOSED_BREAK_COUNT`）就把封闭计时清零。
- 既不是双墙、也不是明确开口（不确定区）：打断计数直接清零。偶发的一帧噪声不会拆掉这段长走廊。

所以“3 格封闭”指的是中间没有被连续 3 次开口打断的那一段。一条走廊中间若有一个真实侧路口，计时会从路口之后重新累加，短死胡同因此凑不满 3 格。

`RUN_LIMIT_MS = 0` 表示不看总运行时间。改成非 0 之后，`timeOK()` 发现超时会 `fail(6)`。转弯循环里也会调用 `timeOK()`，所以超时可以发生在转动过程中。

## 9. 上一张地图的状态（第 192–198 行）

只在 `NORMAL_MAZE_MODE == false` 时有意义。

- `mapRouteStep`：固定路线的下标。0 到 6 是 7 次路口转向，变成 7 之后主循环不再找路口，只按时间往前开。
- `mapOutboundFirstLegMs`：第一次路口之前，真实前进了多久。
- `mapReturnTargetMs`：返程要开多久。

第一步记时间时会减去 `SIDE_REARM_MS`。因为 `setup()` 把 `afterDepartForwardMs` 预先写成了 250，如果不减，返程会多开这 250 ms。减去之后，返程长度对应的是起步之后真实测到的去程。

`calculateMapReturnTarget()` 再把这个时间加上 `MAP_RETURN_TRIM_MS`。去程先被截断到 1 小时，避免异常大的数。补偿是有符号的 `long`，可以是负的；加完小于 1 就改成 1 ms。最后转回无符号毫秒。

### 知识点：有符号减法 / Signed Arithmetic 与无符号回绕 / Unsigned Wrap

**中文**

`afterDepartForwardMs` 是 `unsigned long`。补偿 `MAP_RETURN_TRIM_MS` 的类型是 `long`，允许写成负数，用来把返程整体缩短。如果直接用无符号数减去一个更大的数，结果按模 2^32 回绕，大约是 40 亿毫秒，而不是一个小的正数。函数因此先把去程转成有符号的 `long`，加上可能为负的补偿，小于 1 再改成 1，最后才转回无符号毫秒。

`subtractWithoutUnderflow()` 是同一问题的另一种写法。1 号路口要把居中时间减去 120。现在的基础值是 1110，减完是 990，不会穿过去。函数仍然先比较：被减数小于或等于减数时返回 1。这样以后若有人把基础时间改小，或者几个提前量叠在一起，无符号减法也不会绕成一个接近 2^32 的居中时间。那种时间意味着车会一直向前开。

**English**

`afterDepartForwardMs` is unsigned, while the map-return trim is a signed `long` so it can be negative. Unsigned subtraction wraps modulo 2^32, so subtracting too much jumps to a value near four billion instead of a small positive delay. The function therefore adds the trim in signed arithmetic, forces the result to at least 1 ms, and only then converts it back. `subtractWithoutUnderflow()` does the same job for the 120 ms early turn: if the centering time were ever smaller than the trim, it returns 1 ms instead of a wrapped multi-week delay.

## 10. START 1 路线跟踪（第 200–214 行）

`start1RouteStage` 是挂在 DFS 外面的一台只向前走的状态机。它不积分位移，也不同陀螺问车在哪一格。它只在两处偷看 DFS：

- 看到左侧开口、正在算对中时间时，用当前阶段决定减 120 ms 还是加 180 ms。这一下发生在选边之前。
- DFS 已经选定出边、还没 `depart()` 时，看这次航向、扫描和相对转向像不像地图上的下一跳。像，阶段加 1。这一下发生在对中结束之后。

所以补偿和阶段升级不是同一时刻。1 号的提前量用在阶段仍是 0 的那次左开口上；选定左转之后阶段才变成 1。3 号的延后量用在阶段已经是 2 的那次左开口上；选定左转之后阶段才变成 3。阶段只升不降。真实路线如果多出一个形状相同的 T 字，补偿会提前用在那个口上，程序没有第二套定位来发现。

| 阶段 | 程序的假设 |
|---|---|
| 0 | 还在等一件事：从 START 2 那侧退回 1 号，并且在 1 号选择左转 |
| 1 | 已经走上边那条路，正在等一个像 2 号的路口 |
| 2 | 已经把某个路口当成 2 号，正在等 3 号 |
| 3 | 3 号的那次左转已经选过，补偿结束 |

升级发生在 `updateStart1RouteBeforeDepart()`，而且必须按 0→1→2→3 的顺序。一次调用最多升一级。

**升到 1：** 调用前 `expectingJ1Return()` 为真，并且这次相对转向是 3（左转）。`expectingJ1Return()` 自己要求：补偿开着、阶段还是 0、`travelKind == 1`（正在退回）、`stackTop == 1`（栈里只有第一个真实路口）、`heading == 2`（车头朝图右）。朝图右时的左转，绝对方向是图上。这就是注释里的“从 START 2 一侧回来后左转”。

**升到 2：** 阶段 1、正在探索、车头朝图左、扫描是左开前墙右开、又选择左转。

**升到 3：** 阶段 2，其余条件和升到 2 相同。注释认为这次左转是进入 3 号下方的死胡同。

`phaseUsesJ3Trim` 不表示“车在 3 号”，只表示**这一次**阶段 2 的计时里加过 180 ms。主循环用它决定贴墙时该报故障 13，还是该立刻当路口处理。`depart()` 一出发就会把它清掉。

补偿加在看到左开口的那一刻，阶段升级加在稍后真正选定左转的那一刻。所以 3 号的 +180 ms 发生在阶段已经是 2、车正朝图左去看下一个左开口的时候；选定那次左转之后阶段才变成 3。1 号的 −120 ms 发生在阶段仍是 0、条件符合“正在退回 1 号”的时候；选定左转之后才变成 1。

如果真实探索顺序和这张地图的假设不一致，阶段会停在旧值，或者在一个形状碰巧相同的路口上升级。程序没有第二套传感器来发现这件事。

## 11. 路口栈（第 216–233 行）

`junctions[32]` 是 DFS 的显式栈，不是隐式的函数调用栈。搜索走到哪，`stackTop` 就指向哪一格，断电前这些记录都在这块数组里。它不是“下一个空位”的指针：0 号格永远放哨兵根，第一个真实路口写入 1 号格。再往上最多到 31。入栈前若 `stackTop + 1 >= 32`，故障 7，不再继续展开。

每一格存四样东西。`openMask` 是第一次到达时的开口签名。`triedMask` 是已经出发过的方向，来路在 push 的同一刻就写进去。`parentDir` 是父边的绝对方向，pop 时车要转回这个方向。`signatureKnown` 表示这格签名能不能拿来做退回核对；哨兵根是假，真实顶点是真。

`travelKind`：

- `0`：这条腿是走向一条还没探索完的新方向。到达路口时入栈。
- `1`：这条腿是退回更早的路口。到达时不入栈，先核对栈顶的开口形状。

`heading` 的含义见文首的表。它和 `lastPhysicalTurn` 一起，是程序对“刚才车身发生了什么”的全部记忆。

### 起点那个虚拟路口

`setup()` 把 `junctions[0]` 设成：

- 只有出发方向（图左）算通的。
- 这个方向已经放进 `triedMask`。
- `parentDir = 255`，没有来路。
- `signatureKnown = false`。

效果是：上电后不会在起点做一次路口决策，车直接往前开。将来如果一路退回到这个节点，它没有父方向，决策函数报故障 12。起点的形状也不可信，不能拿去和某次扫描比对。

## 12. 运动状态（第 235–262 行）

`phase`、`phaseStartedAt`、`phaseCenterTime` 是第 7 节那台状态机的数据。`phaseStartedAt` 在进入阶段 1 或阶段 2 时写成 `millis()`。阶段 2 还要把计划开多久放进 `phaseCenterTime`。

`halted` 为真后，主循环前几行就返回，轮子保持停止。`finished` 只有成功终点会置真。故障路径只置 `halted`。`faultCode` 的初值是 6，如果在跑起来之前就停，灯语按故障 6 处理。

### 知识点：只把“轮子在往前转”的时间算进路程

`forwardActive` 在 `driveCorrected()` 里置真，在 `stopRobot()` 里置假。`accountMotion()` 用 `millis()` 算出距离上次记账过了多久，然后把 `accountAt` 更新成现在。只有 `forwardActive` 为真，这段时间才加进：

- `afterDepartForwardMs`：这次 `depart()` 以来的前进时间。侧开口重臂、终点最短行程、旧地图返程都看它。
- `enclosedForwardMs`：其中 `enclosedNow` 为真的部分。长死胡同看它。

转弯时 `turnTo()` 先 `stopRobot()`，再堵在 `while` 里转。这段自旋不会加进路程。停车读传感器也不会。

一帧里可能调用好几次 `accountMotion()`，例如侧边跟踪开头一次，真正写电机时又一次。因为每次都把 `accountAt` 拨到当前时刻，时间被切成几段相加，不会重复计算。

`lastPhysicalTurn` 在 `turnTo()` 末尾写成相对转向：0 没转、1 右转、2 掉头、3 左转。主循环用“上一次是不是右转，而且这条腿是否短于两格”来决定要不要多开 100 ms。

`runStartedAt` 配合 `RUN_LIMIT_MS`。当前时限是 0，`timeOK()` 只在已经 `halted` 时返回假。

## 13. 侧开口跟踪（第 264–280 行）

这一组变量解决的是：“侧向接收头会在开口旁边连续看很多帧，怎样只触发一次，并且下一次真的进入走廊之后还能再触发。”

| 变量 | 作用 |
|---|---|
| `leftOpenVotes` / `rightOpenVotes` | 该侧连续多少帧已经是明确开口。到 3 才可能成为事件。中间一帧不是明确开口就清零 |
| `leftWallVotes` / `rightWallVotes` | 该侧连续多少帧 `hasWall`。到 3 就把 latch 清掉 |
| `leftLatched` / `rightLatched` | 这个开口已经接过手。为真时，即使投票已经到 3，也不再触发 |
| `leftCandidate` / `rightCandidate` | 当前这次居中是由哪一侧引起的。时间到了还要再确认这一侧仍然开着 |
| `tJunctionExtra` | 居中途已经看到 T 字，最终时间要加 80 ms |

### 知识点：锁存器 / Latch，以及重新武装 / Re-arm

**中文**

锁存器（latch）是一种记忆电路：置位（set）之后输出保持为真，直到复位（reset）把它打开。软件里的 `leftLatched` 做的是同一件事，只是记忆放在变量里。

发现开口时把对应侧置位。阶段 2 期间主循环会先处理阶段 2 并返回，同一帧本来也不会再次进入“发现新开口”。锁真正起作用的是出发之后：`seedSideTracking()` 把“当前没有墙”的那一侧直接置位。刚离开路口时，旁边看到的开口就是刚离开的那个路口。锁住之后，必须连续 3 帧 `hasWall`，latch 才变回假。这个动作在代码常量里叫 re-arm，重新武装：检测器回到可以再次触发的状态。中间的不确定帧会把墙计数清零，单独一帧噪声不能完成复位。

开口计数也有对称的消抖：必须连续 3 帧 `isOpen`，而且 latch 为假，才产生事件。一帧不确定会把开口计数清零。它既不帮助触发，也不帮助重新武装。

**English**

A latch is a memory element that stays set until an explicit reset. `leftLatched` is the software version: seeing a new opening sets it, and only three consecutive wall frames clear it. The constant name re-arm means the detector is allowed to fire again. The important moment is departure. `seedSideTracking()` sets the latch on any side that is not currently a wall, so the opening the robot just left cannot immediately count as a new junction. An uncertain frame clears both the open-count and the wall-count, so it neither triggers an event nor completes the reset.

## 14. 扫描窗口（第 282–288 行）

DFS 用的签名不吃单帧红外。单帧会在墙和开口之间跳，直接拿去选边，车会朝一帧噪声转弯。`scanWindow[7][3]` 先把最近的分类存下来：三列是左、前、右，格子里是 −1（不确定）、0（墙）或 1（开口）。`windowIndex` 是下一次要写的位置，写到 7 就回到 0，覆盖最旧的一帧。`windowCount` 从 0 涨到 7 后不再增加。不满 7 帧时，投票函数直接返回 −1，`serviceJunction()` 看到 −1 就故障 2，宁可不转。侧向要 7 帧里至少 5 帧一致，前向要至少 6 帧一致，前向更严，因为前墙会启动接近阶段。

### 知识点：环形缓冲 / Ring Buffer

**中文**

环形缓冲（ring buffer，也叫 circular buffer）用一块固定长度的数组保存最近的记录。写到最后一格，下标就对长度取模，回到 0，覆盖最旧的一格。它不需要每来一帧就把后面的元素全部搬家。这里 `windowIndex` 就是写指针，`windowIndex` 到达 7 时被写成 0，等价于对 7 取模。

投票不看先后，只数 7 格里有几个 0、几个 1，所以覆盖旧数据之后，窗口里留下的就是最近 7 帧。`windowCount` 在未满时单独记录已经写入多少格。不满 7 就不投票，避免把还没写过的格子算进多数。

`clearScanWindow()` 只把计数和写下标清零，不逐格擦掉旧数字。因为 `windowCount < 7` 时 `windowState()` 直接返回 −1，那些残留数字不会被读到。转向和出发都清窗口，避免转弯前的走廊帧和转弯后的帧混进同一次多数表决。

**English**

A ring buffer, or circular buffer, stores the newest samples in a fixed array. The write index wraps with modulo arithmetic and overwrites the oldest sample, so the elements do not have to be shifted. `windowIndex` is that write index. The vote ignores order and only counts zeros and ones, so the wrapped array is the latest seven frames. `windowCount` blocks the vote until all seven slots have been written. `clearScanWindow()` resets the count and the index without erasing leftover numbers; the count check makes those leftovers unreadable. Turns and departures clear the window so frames from the old heading cannot vote together with frames from the new one.

## 15. 基础函数（第 290–386 行）

这一组函数不读红外，也不选边。它们给后面的运动、故障和 START 1 猜测提供最小操作：方向变位、切一段前进时间、停车、清纠偏、报故障、看时限、成功结束、判断补偿阶段、做一次不会绕回的减法。

### `bitFor`（第 294–296 行）

第 295 行返回 `(uint8_t)(1U << direction)`。方向 0 左移 0 位，数值是 1；方向 1 是 2；方向 2 是 4；方向 3 是 8。`1U` 是无符号的 1，避免有符号左移的未定义行为。调用方保证方向只是 0 到 3，所以结果一定落在低 4 位里。

后面“这个方向通不通、走过没有”都拿这个掩码做与、或、异或。`setup` 用它写哨兵根，`scanOpenMask` 用它把扫描收成绝对方向，`serviceJunction` 用它标记已走过的边，`returnSignatureMatches` 用它把正后方从核对里抹掉。

### `accountMotion`（第 298–310 行）

第 299–301 行用现在减去上次记账时刻，得到 `dt`，然后把 `accountAt` 拨到现在。一帧里调用好几次也不会重复计算，时间被切成几段相加。

第 303 行：`forwardActive` 为假就返回，这段 `dt` 丢掉。转弯、停车、故障之后的空等都不算路程。

第 305 行把 `dt` 加进 `afterDepartForwardMs`，这是这次出发以来的前进时间，也是旧地图第一段去程的原料。第 307–309 行只在 `enclosedNow` 为真时，把同一段再加进 `enclosedForwardMs`。左右都是墙的走廊才算进死胡同长度；自旋前会先停车，那一千多毫秒因此进不了 3 格判据。

### `stopRobot`（第 312–318 行）

## 16. 红外读取（第 388–449 行）

这里把一次载波采样收成两个整数，再收成墙、开口或贴墙。主循环一帧调用三次 `readSensor`，左、前、右加起来大约几十毫秒。阶段 2 和阶段 1 的时间用 `millis` 量，这几十毫秒已经算进行驶时间，不需要再加。这段时间里车仍按上一帧的脉宽在走，所以主循环先读前方：贴墙就立刻停车，再去读左右。

### `irRead`（第 392–403 行）

这是最小的一次测量，只服务 `readSensor`。

1. 第 393 行 `tone(tx, frequency)` 让发射脚输出指定频率的方波，红外灯就以这个频率闪。频率来自第 116–118 行的 38、39、40、41、42 kHz。
2. 第 394 行等 700 微秒。38 kHz 下大约是二十多个周期，接收头才认得出这段猝发。
3. 第 396 行读接收脚。`LOW` 是有反射，这是主动低电平解调，不是 UART 的 TX/RX。
4. 第 398–401 行关掉发射，把脚拉低，再空 250 微秒，避免下一次测量和这一次粘在一起。
5. 第 402 行把这一次的电平交回去。

左右前三路不会同时发射。`tone` 一次只用一个脚，`readSensor` 也是串行调用它。

### `readSensor`（第 405–425 行）

第 406 行把 `Reading` 的 `bands` 和 `votes` 都清成 0。外层第 408 行走 5 个频率，内层第 411 行走每个频率 3 次，一共 15 次 `irRead`。

第 412–414 行：这一次是 `LOW`，`hits` 加 1。第 417 行不管够不够 2，`hits` 都加进 `votes`。所以 `votes` 是 15 次里成功的总次数，范围 0 到 15，给纠偏当“有多近”用。第 419–421 行：`hits >= 2` 这个频率才算一个 band。一个频率里 3 次有 2 次成功才算有效，这是小范围多数表决。`bands` 因此是 0 到 5，表示有几个频率还能解调。墙越近，两个数通常越大。

### 四个判断（第 427–450 行）

**`hasWall`（第 427–430 行）** 两个条件是“或”：`bands >= 2`，或者 `votes >= 3`。稍有反射就倾向认为旁边是墙，好让纠偏早点有反馈。`driveCorrected`、`updateSideTracking`、`seedSideTracking`、`depart` 用它。

**`isOpen`（第 432–435 行）** 比墙严。`bands` 必须是 0，并且 `votes` 不超过 1，两个都要成立。几乎没反射，才承认这里是缺口。主循环要连续 3 次 `isOpen`，而且这一侧没有被锁住，才把车推进阶段 2。

墙和开口之间故意留空。例如 `bands` 是 1、`votes` 是 2，两个函数都是假。这种读数不拿来触发开口，也不拿来重新武装。

**`tooClose`（第 437–440 行）** 比“前方有墙”严得多。有墙只要 `bands >= 3`，会进入阶段 1，再慢开 1.2 格。贴墙要求五个频率全中，而且 15 票里至少 14 票，说明鼻子已经顶到墙上。主循环一发现贴墙就停车，不再等那 1.2 格。唯一的例外是 3 号延后还没走完，那时直接故障 13。`depart` 转完也会用它检查鼻子是不是对着墙。

**`classifySide`（第 442–446 行）** 扫描窗口不存原始票数，只存分类。第 443 行先问 `hasWall`，有墙返回 0。第 444 行再问 `isOpen`，开口返回 1。第 445 行其余返回 −1。按现在的门槛，`bands >= 2` 不可能再满足 `bands <= 0`，墙和开口不会同时成立。−1 会留在窗口里，但投票时两边都不算。

**`classifyFront`（第 448–450 行）** 前向单帧没有不确定这一档。第 449 行 `bands >= 3` 返回 0，否则返回 1。程序希望早点开始减速，而不是停在不确定里继续全速。窗口里的前向仍然可能是 −1，那是 `windowState` 的结果：7 帧还没满，或者同意墙的不足 6 帧、同意开的也不足 6 帧。

## 18. 直行纠偏 `driveCorrected`（第 559–644 行）

这是唯一让车进入前进状态的函数。`halted` 时直接返回，避免故障之后还有别的路径把轮子再打开。

步骤对应第 6 节的知识：

1. 用左右是否有墙组成 `mask`：左墙占数值 2，右墙占数值 1。和上一帧不同就重置滤波器。
2. 按双墙、单左、单右计算原始误差。双无墙则在平滑之后把滤波值和修正清零。
3. 按百分比算前进偏移。  
   `lOff = (1548 − 1490) × percent / 100`  
   `rOff = (1490 − 1438) × percent / 100`  
   整数除法会丢掉小数。100% 时大约是左 +58、右偏移 52。85% 时大约是左 +49、右偏移 44。
4. 修正上限取“双墙 22 或单墙 20”和“较小前进偏移减 5”里更小的那个。前进偏移太小就把上限压到 0，只直行不纠偏。
5. 死区、比例、限幅、再按每帧最多 6 微秒逼近目标。
6. 记账，`forwardActive = true`，写两个舵机：

```text
左脉宽 = 1490 + lOff + correction
右脉宽 = 1490 − rOff + correction
```

右轮写成减去 `rOff` 再加 `correction`。`correction` 为正时右脉宽上升、右轮前进变慢，左轮变快，车向右。这和“正误差表示偏左、应该向右修”是配在一起的。

百分比只在三个地方出现：出发和路口前后用 85，空旷直行用 100，接近阶段也是 85。没有别的速度档。

## 19. 侧墙和开口跟踪（第 646–734 行）

这两个函数不选边，也不写舵机。它们给主循环准备三样东西：这一帧算不算封闭走廊、左右开口连续了几次、哪一侧的 latch 还锁着。封闭走廊的 3 格判据见第 8 节，开口和重新武装的含义见第 13 节。

### `updateSideTracking`（第 650–719 行）

主循环每帧都调用它，参数是这一帧的左、右、前读数。函数体没有使用 `front`，前墙的接近和贴墙留在主循环里处理。它不决定转弯。

第 653 行先 `accountMotion`。读传感器花掉的时间因此也能算进路程，而且发生在下面可能把 `enclosedNow` 改掉之前，所以这一段仍按上一帧的封闭状态入账。

第 655–659 行看左右是不是墙、是不是明确开口。四个布尔互不替代：有墙用 `hasWall`，开口用更严的 `isOpen`。

第 661–678 行管封闭计时。左右同时是墙，`enclosedNow` 为真，打断计数清零。主循环里随后的前进时间会累加到 `enclosedForwardMs`。一旦不是双墙，第 665 行先把 `enclosedNow` 写成假。这时若某一侧已经是明确开口，打断计数加 1，上限是 `ENCLOSED_BREAK_COUNT`（3）。加到 3 就把封闭计时清零，这条长走廊作废。左右都不是明确开口，只把打断计数清零。不确定的帧因此拆不掉已经攒下的死胡同长度，偶发噪声要连续 3 次开口才拆得掉。

第 680–694 行是开口连续计数。这一侧 `isOpen` 就加 1，停在 `SIDE_OPEN_CONFIRM`（3），否则清零。主循环要看到计数等于 3、而且这一侧没有 latch，才把该侧当成新开口候选。计数停在 3，不会在长缺口里涨到 255 再绕回 0。

第 696–718 行是重新武装。某一侧 `hasWall`，墙计数加 1，停在 `SIDE_WALL_REARM_COUNT`（3）。加到 3 就把这一侧的 latch 清掉，允许检测下一个开口。这一侧不是墙，墙计数清零，连续 3 帧被打断。不确定帧同样不能用来开锁。

### `seedSideTracking`（第 721–734 行）

`depart` 末尾和 `setup` 读完第一帧之后调用。刚离开一个路口时，旁边看到的缺口就是刚离开的那个口，不是新路口。

第 723–724 行：没有墙的那一侧 `leftLatched` 或 `rightLatched` 写成真。判断用的是 `!hasWall`，不是“已经是明确开口”。不确定也先锁上，避免出门时含糊的侧向读数立刻变成新路口。有墙的那一侧 latch 为假，之后出现的新开口可以触发。锁上之后，必须先连续看到 3 帧墙，`updateSideTracking` 才把 latch 打开。

第 726–733 行把左右开口票、墙票、候选标志全部清零。出发后的第一段还有第二层保护：`afterDepartForwardMs` 从 0 重新计，接下来 250 毫秒内，新的侧开口事件不会被接受。`setup` 是例外，它把已行驶时间预先写成 250，所以起步后的第一个侧开口不用再白等这段重臂时间。

## 20. 转向 `turnTo`（第 736–797 行）

航向更新是开环的。DFS 给出一个绝对方向 `target` 之后，`turnTo()` 并不测量车头现在的角度。它只做一次模运算：

```text
相对转向 = (target - heading + 4) % 4
```

前面加 4，是为了相减之后仍是非负数。余数把两个绝对航向折成一个动作：0 已经对准，1 右转 90°，2 掉头，3 左转 90°。然后给左右轮一组固定脉宽，阻塞等到对应的毫秒，再把 `heading` 写成 `target`。时间到了就相信角度到了。没有用红外看转完后左右墙是不是换到了预期的一侧。

- 0：已经对着目标，不停车、不改别的状态，返回真。
- 1：右转脉宽，持续时间 `RIGHT_TURN_MS`，只亮右灯。
- 3：左转脉宽，持续时间 `LEFT_TURN_MS`，只亮左灯。
- 2：左转那组脉宽，持续时间 `UTURN_LEFT_MS`，左右灯都亮。

进入转弯先停车并清纠偏，避免直行修正脉宽和旋转脉宽叠在一起。旋转过程中每 1 ms 看一次 `timeOK()`。转完再停车，`delay(150)` 等车身稳定。

然后才更新状态：

- `heading = target`
- `lastPhysicalTurn = 相对转向`
- 封闭走廊计时和“当前在封闭里”全部清掉。转弯原地转，不应该算进死胡同长度。
- 扫描窗口清掉。

返回值是转完之后 `timeOK()` 的结果。时限若在转动中触发，`fail()` 已经把车停下，这里返回假，调用者不再 `depart`。

这里不读陀螺仪，也不用红外检查是不是真的转了 90°。时间到了就相信角度是对的。

## 21. 从路口出发 `depart`（第 799–849 行）

参数 `direction` 是绝对方向，`kind` 是出去探索（0）还是退回（1），`oldL` 和 `oldR` 是决策时的左右读数。

1. 如果目标方向和车头不同，`turnTo()`。失败就整段失败。
2. 转过之后，旧的左右读数已经对着别的墙，不能再用。程序重读前方。贴墙就等 40 ms 再读；仍然贴墙则故障 3。40 ms 是在排除转向刚停时的一次误触发。
3. 重读左右，把这一帧推进已经清空的窗口，并用这一帧设置 `enclosedNow`。窗口这时只有 1 帧，还不能拿来做下次路口决策。
4. 没转向就继续用决策时的左右读数。车头没变，那两份读数仍然对着原来的墙。
5. 记账，把 `travelKind` 设成这次的 `kind`，路程从 0 开始。
6. 阶段回到 0，T 字加时和 3 号补偿标记清掉。
7. 按当前左右读数播种锁存，以 85% 速度开走。

`afterDepartForwardMs = 0` 发生在播种之前。接下来的 250 ms 里，即使播种没有锁住某一侧，新开口事件也不会被接受。出发后的第一段路因此有两层保护：锁存，加上时间重臂。

## 22. 路口栈辅助（第 851–892 行）

**`scanOpenMask()`** 把车头相对的左、前、右换成绝对方向，再收成掩码。

后方永远置位。注释写明：后方是来路，不是这颗传感器测到的。车能从那里开到这里，就认为那里是通的。

左、前、右只有扫描值等于 1 才置位。扫描是 0（墙）或调用时已经被要求有效，所以不会把 −1 写进掩码。

**`returnSignatureMatches()`** 用在退回路口：

1. `signatureKnown` 为假，直接失败。起点虚拟路口因此永远对不上。
2. 算出当前车头的正后方。
3. `0x0F & ~bitFor(back)` 得到低 4 位里“除了正后方”的三个方向。
4. `openMask ^ observedMask` 标出所有不一致的位。再和上一步相与，把正后方那一位从比较里拿掉。
5. 结果为 0，才表示左、前、右对应的绝对方向和当初记录的一样。

正后方被排除，是因为这一位在新扫描里是“假定来路为开”，不是重新测到的。比对的是传感器真正看到的三个方向。

### 一次掩码例子

车头朝图右，`heading = 2`。相对左是图上（1），前是图右（2），相对右是图下（3），后是图左（0）。扫描为左开、前墙、右开。

- 掩码 = 后 + 左 + 右 = 方向 0、1、3 = `00001011`。
- 若当初记录的也是这三个方向开、方向 2 关，异或后是 0，核对通过。
- 若当初方向 1 是关的，而现在看到开了，异或在方向 1 那一位是 1，核对失败，故障 8。

## 23. 旧地图返程时间（第 894–911 行）

`calculateMapReturnTarget` 只在 `NORMAL_MAZE_MODE` 为假、而且 `serviceJunction` 走到固定路线第 0 步时调用。普通 DFS 不看它。第一段去程量出来之后，返程开同样久，再用 `MAP_RETURN_TRIM_MS` 做整体加减。当前补偿是 0。去程在调用前已经减去 `SIDE_REARM_MS` 那 250 毫秒种子，所以返程目标等于去掉种子之后的第一段时间。算术和有符号回绕见第 9 节。按行是：

1. 第 900–902 行：去程超过 1 小时就截断成 3600000。避免一个异常大的无符号数在下一步转成 `long` 时溢出。
2. 第 904 行：先转成 `long`，再加可能为负的补偿。去程是无符号毫秒，补偿是有符号的 `long`，不能直接用无符号减法。
3. 第 906–908 行：结果小于 1 就改成 1。负补偿把时间减穿时，不会留下 0，更不会留下绕回去的四十多亿。
4. 第 910 行：转回 `unsigned long`，交给主循环第 1371 行附近的返程计时。走到第 7 步之后，主循环只比较已前进时间和这个目标，不再进路口决策。

## 24. 选定方向时更新路线（第 913–960 行）

`updateStart1RouteBeforeDepart` 在 `serviceJunction` 里、`depart` 之前调用。此时 `heading` 还是旧车头，参数 `direction` 是已经选定、尚未转过去的绝对方向。阶段含义和 1 号、3 号补偿的时机见第 10 节。这个函数不测量位置，也不改栈。

第 921 行：补偿没开就直接返回。旧地图因此不会升级 `start1RouteStage`。

**升到 1（第 926–930 行）。** 阶段还是 0，而且调用前 `serviceJunction` 已经把 `wasJ1Return` 记成真，这次相对转向又是 3。`wasJ1Return` 来自 `expectingJ1Return`：正在退回、栈深只有 1、车头朝图右。朝图右时的左转，绝对方向是图上。

**升到 2（第 936–944 行）。** 阶段是 1，正在探索，车头朝图左（`heading == 0`），扫描是左开、前墙、右开，又选了左转。注释把这次左转当成前往 3 号方向。

**升到 3（第 950–958 行）。** 阶段是 2，其余条件和升到 2 写得一样。区分它们的只有当前阶段。注释认为这次左转是进入 3 号下方的死胡同。程序相信探索顺序会先遇到一个这样的 T 字（当成 2 号），再遇到下一个形状相同的 T 字（当成 3 号）。中间若多出一个同样的口，3 号补偿会提前用掉，没有第二套定位来发现。

补偿本身不在这个函数里加减。减 120、加 180 发生在更早的主循环里，当时阶段还没升。这里只是在真正选定那次左转之后，把阶段向前拨一格。

## 25. 路口决策 `serviceJunction`（第 962–1137 行）

这是 DFS 的转移函数，一次调用把“车已经站在一个顶点上”变成“车开始沿下一条边离开”。入口先看签名合不合法。左、前、右任何一路仍是 −1，说明 7 帧投票还没形成多数，故障 2，轮子停，栈不动。合法之后先 `accountMotion()`，把对中或贴墙前的最后一段前进记进航位。不记的话，这条边的长度会少掉决策前那几十毫秒，长死胡同的 3 格判据会偏短。

第四个参数 `safetyStopped` 表示这次决策是不是“因为贴墙才停下来的”。贴墙路径要求前方扫描必须是墙，否则故障 4。侧开口正常走完居中时间时，这个参数是假；停车复扫时，如果当时前方也已经贴墙，则会传真。

### 旧地图分支

`route[7] = {1, 1, 1, 2, 3, 3, 3}`，依次是右转、右转、右转、掉头、左转、左转、左转。

每一步：

1. 步数已经到 7 还进了这个函数：故障 11。正常走完 7 步后，主循环自己计时返程，不应该再进决策。
2. 这一步若是掉头，扫描必须左、前、右都是墙。掉头被当成“前面是死胡同”的动作，不是在十字路口中间掉头。
3. 目标绝对方向 = `(heading + relative) % 4`，而且这一位在开口掩码里必须是 1。写死的路线和传感器矛盾，就故障 11，不会硬转进墙。
4. 第 0 步时，已前进时间必须大于 250 ms，然后记下去程并算出返程目标。
5. 步数加 1，`depart` 出去。`kind` 固定为 0，不使用栈。

### 普通模式分支

先检查长死胡同终点。成立就成功结束并返回假。调用者看到返回值假时，车已经 `halted`，不会再往下开。

然后处理探索或退回。

**`travelKind == 0`，正在探索**

检查再入栈会不会超过 31。会，就故障 7。然后 `stackTop++`，在新格子写入：

- `openMask = 现在扫到的掩码`
- `triedMask = 只有来路这一位`
- `parentDir = 来路`
- `signatureKnown = true`

来路 = `(heading + 2) % 4`，也就是当前车头的反方向。车是沿着这条腿开进路口的，退回时要朝这个绝对方向转回去。

**`travelKind == 1`，正在退回**

`stackTop == 0` 是故障 9：退回模式却已经站在起点记录上。否则用 `returnSignatureMatches()` 对比栈顶。失败是故障 8，栈不动，车停。成功则不修改掩码，继续在这个旧路口上选下一条路。

这里有一个顺序要求：`wasJ1Return = expectingJ1Return()` 必须写在 `stackTop` 或 `travelKind` 被改掉之前。1 号判断要看“还没入栈、也还没出栈”的深度和退回标志。

**选一条还没走过的路**

候选顺序写死在 `order[3]`：

1. `(heading + 3) % 4` 左转
2. `heading` 直行
3. `(heading + 1) % 4` 右转

一个方向要同时满足四件事才出发：

- 现在的掩码里它是开的。
- 记录里的 `openMask` 它也是开的。探索刚入栈时，这两份是同一份。退回时，记录是第一次来的时候写的，现在的扫描必须仍然认为它开着。
- `triedMask` 里还没有它。
- 它不是 `parentDir`。来路虽然在记录里通常是开的，但不能被当成新探索方向。

选中之后立刻把该位置进 `triedMask`，更新 START 1 阶段，`depart(direction, 0)`。返回真表示车已经开始新的一条腿。

**没有可选方向**

退向 `parentDir`。父方向是 255，故障 12。父方向在当前扫描掩码里是 0，故障 10，表示来路现在看起来被堵住了。`stackTop == 0` 再检查一次，故障 12。否则栈顶减 1，`depart(来路, 1)`。减栈发生在出发之前：出发之后的“当前路口”已经是更早的那个，到达时核对的就是它。

### 一个小迷宫上的栈

下面只说明栈的进出，不对应某一张真实地图。S 是起点，车向北出发。第一个路口 A 可以西和北，来路在南。第二个路口 B 只能向东，来路在南。

1. 到达 A，探索入栈。栈是 `[起点, A]`。A 的来路南已经标成走过。优先西，向西出发，`travelKind = 0`。
2. 到达 B，入栈。栈是 `[起点, A, B]`。B 没有西、没有北，只有东，向东走。
3. 东边是死胡同，再次决策时那条腿的 `travelKind` 仍是 0，会先把死胡同口入栈，发现除了来路没有别的开方向，于是出栈并退回 B。
4. 回到 B 时 `travelKind` 是 1，核对 B 的形状，不再入栈。B 的东已经走过，无路，再出栈，退回 A。
5. 回到 A，核对形状。西已经走过，北还没走，于是向北出发，重新变成探索。

左、前、右的优先顺序会改变第 2 步先走哪条，但“走到底再退回、退回后试下一条”这个结构不变。

## 26. 前方过近 `handleTooClose`（第 1139–1178 行）

主循环在读完左右、更新跟踪之后，如果这帧一开始就判定贴墙，会进到这里。车在函数开头再次停车。

1. 取当前窗口。它和最后一帧的瞬时分类不一致，就停车重扫。
2. 重扫失败：如果还没因为别的原因停下，故障 4。
3. 重扫成功后再读一次三向，推进窗口，再算一次扫描。这次仍必须和最后一帧一致，否则故障 4。
4. `timeOK()` 通过后，`serviceJunction(..., safetyStopped = true)`。

贴墙因此被当成“前墙路口已经到了”，不再补开那 1.2 格。阶段 1 是“远远看到前墙，还有距离”。`tooClose` 是“再开下去会顶上”。两条路径最后都进入同一个决策函数。

3 号的例外不在这个函数里。主循环在调用它之前，如果阶段 2、带有 3 号加时、而且计划时间还没到，就直接故障 13。那样不会提前旋转。时间其实已经到了，即使带着 3 号加时，贴墙仍会走进这个函数。

## 27. 侧开口停车复扫 `rescanSideJunction`（第 1180–1220 行）

阶段 2 时间到了，但出现下面任一情况，就不用边走边决策，改走这里：

- 当初引起居中的那一侧，现在的单帧已经不是 `isOpen`。
- 窗口结论和最后一帧不一致。

流程和贴墙重扫相似：停车、最多 3 轮、再读一次、窗口必须匹配最后一帧。失败且尚未故障时，是故障 2。

匹配之后还要检查候选侧：

- 当初是左侧候选：窗口左侧必须是开，而且最新左读数 `isOpen`。
- 右侧同理。
- 两侧都是候选时，有一侧仍满足就算数。

候选消失是故障 1。这是为了避免“当时好像有个口，停稳一看是墙，却仍然转弯”。通过后把 `tooClose(front)` 当作 `safetyStopped` 传给决策。居中时间结束的同时鼻子已经贴住前墙，决策函数仍会按安全停车的规则要求前方扫描是墙。

## 28. 初始化 `setup`（第 1222–1302 行）

顺序和原因：

1. 三个发射脚输出并拉低，三个接收脚输入，三盏灯输出。先拉低发射，避免 `attach` 舵机之前红外灯处于不确定电平。
2. `attach` 左右舵机。`accountAt = millis()` 后停车。停车会记账，此时还没开始前进，记账结果是 0。
3. 灯灭，`delay(1000)`。这一秒给舵机和传感器稳定，也让人有时间松手。
4. 车头设为 0，栈顶设为 0，写入第 11 节的虚拟起点。`travelKind = 0`。
5. 旧地图步数、START 1 阶段、阶段机、封闭计时、上一次转向全部回到初始值。扫描窗口清空。
6. 读一次前、左、右。用左右播种锁存，并把这一帧推进窗口。若左右都有墙，`enclosedNow` 置真。
7. `afterDepartForwardMs = SIDE_REARM_MS`。起步后的第一个侧开口不用再等 250 ms。这 250 不是车真的开过的，所以旧地图记第一段去程时要减掉它。
8. `runStartedAt` 和 `accountAt` 更新到“准备出发”的时刻。前面那 1 秒不计入运行时限，也不计入路程。
9. 前方已经贴墙：故障 6，函数返回，车保持停。起步距离不对，继续开没有意义。
10. 否则 `driveCorrected(..., 85)`。第一段用慢速，直到主循环进入“什么事件都没有”的分支，才改成 100%。

上电后窗口只有 1 帧。阶段 1 或阶段 2 的决策都要求窗口有效，所以至少还要再跑 6 圈主循环，7 帧才会满。只靠 1 帧不能转弯。

## 29. 主循环 `loop`（第 1304 行到文件末尾）

一帧的优先级从上到下，命中就返回，所以靠后的分支看不到靠前的分支已经处理过的情况：

1. `halted`：搜索或故障已经结束，这一帧只维持停车和灯，不再采样。
2. 贴墙：先于一切对中计时。3 号延后还没走完就报故障 13；否则把贴墙当成顶点已到，进入 DFS。
3. 阶段 2：侧开口对中。时间未到只开车；时间到了才允许 DFS。
4. 新的侧开口事件：这才把 Moore 机推进阶段 2。阶段 2 的 `return` 写在它前面，所以对中过程中不会被第二个开口重新计时。
5. 阶段 1：前墙接近，开满 1776 ms 才 DFS。
6. 单帧前向 `bands >= 3`：进入阶段 1。这里还不用 7 帧签名，目的是早点减速。
7. 都没有：100% 的 P 控制直行。DFS 不在这条走廊中途运行。

### 已经停下时的灯

`finished`：三灯常亮。

故障 1 到 5 是固定组合，不闪：

| 码 | 灯 | 是在哪一步停下的 |
|---|---|---|
| 1 | 左 | 侧开口复扫后，候选开口没了 |
| 2 | 中 | 决策时扫描无效；或侧开口复扫失败、复扫后窗口仍和最后一帧不一致 |
| 3 | 左 + 中 | 转完再次读前方，仍然贴墙 |
| 4 | 右 | 贴墙重扫失败；重扫后仍不一致；或贴墙进来时前方扫描却不是墙 |
| 5 | 左 + 右 | 前墙接近时间到了，窗口和最后一帧不一致，或者前方又变成开的 |

故障 6 到 13 共用一套闪法。闪的次数是 `faultCode - 5`：

| 码 | 闪几次 | 含义 |
|---|---|---|
| 6 | 1 | 起步前方就贴墙，或设置了运行时限并且超时 |
| 7 | 2 | 探索入栈会超过 32 个路口记录 |
| 8 | 3 | 退回到的路口和栈顶记录的开口不一致 |
| 9 | 4 | 退回模式下栈顶已经是起点 |
| 10 | 5 | 要退回的来路，当前扫描却是关的 |
| 11 | 6 | 旧地图：步数超出、掉头时不是三面墙、目标方向不通、第一段太短、返程时间是 0 |
| 12 | 7 | 要退回但没有父方向，或已经在栈底 |
| 13 | 8 | 3 号加时还没开完，前方已经贴墙 |

### 知识点：由时间导出状态 / Time-Derived State

**中文**

闪 N 下再灭 2 秒，周期长度是：

```text
cycleMs = N × 500 + 2000
```

`t = millis() % cycleMs` 用模运算把绝对时间折进一个周期。前 `N × 500` 毫秒是闪烁段，后面 2000 毫秒是灭。闪烁段里再看 `t % 500 < 250`：每 500 ms 的前一半亮，后一半灭。占空比大约是 50%。

灯的亮灭完全由当前时间算出来，不另存“已经闪了几下”或“灯现在是亮的”。这种做法没有一份会和真实时间走散的软件计数。主循环在故障分支里每圈 `delay(20)`，所以电平最快大约 20 ms 改一次，人眼仍然看成闪烁。亮灭沿落在采样时刻上，不会精确卡在 250.000 ms。

故障 1 到 5 不用这套周期。它们是静态的电平组合：左、中、右三盏灯的开关直接对应一个码，方便在车上不用数闪烁次数。

**English**

The blink pattern is time-derived state. `millis() % cycleMs` folds absolute time into one period with modulo arithmetic. The first `N × 500` ms blink, and the remaining 2000 ms stay off. Inside a blink, `t % 500 < 250` makes a duty cycle of about 50%. The LED level is computed from the clock, so there is no stored count of flashes that can drift from real time. `delay(20)` in the halted loop samples that pattern about every 20 ms. Faults 1 through 5 do not use the period; each is a static combination of the three lamps.

### 还在行驶时的一帧

**旧地图返程。** `mapRouteStep == 7` 时，先记账。返程目标若仍是 0，故障 11。`afterDepartForwardMs` 达到目标就成功结束。没到就继续往下读传感器。也就是说返程这一段仍然会纠偏、仍然可能因为路口或前墙进入决策；一旦再进决策，步数已经是 7，旧地图分支报故障 11。返程能成功，依赖这段路在时间到之前不再被当成路口。

**读传感器。** `front = readSensor(前方)`。`tooClose(front)` 为真就马上停车，然后才读左右。左右读完，`pushScan` 和 `updateSideTracking` 总会发生，包括贴墙这一帧。贴墙前的最后一段前进因此会进路程计数。

**贴墙分支。** 条件是阶段 2、这次居中使用了 3 号加时、开关开着、并且 `millis() - phaseStartedAt` 还小于计划时间（T 字的话再加 80）。满足就故障 13。否则 `handleTooClose()`。这条分支结束本帧。

**阶段 2。** 每帧都允许把 `tJunctionExtra` 置真，条件是窗口已经有效并且是左开、前墙、右开。这个标志只置真、不置假。时间到了就看候选侧的**单帧**是不是仍然 `isOpen`，以及窗口是不是匹配最后一帧。两个都过，`serviceJunction(..., false)`。有一个不过，`rescanSideJunction()`。时间没到就 85% 继续开。

阶段 2 的 `if` 在“发现新开口”之前，并且结尾有 `return`。居中期间即使另一侧也满足开口事件，也不会重新计算居中时间，也不会把另一侧补进候选。候选只在进入阶段 2 的那一帧写下来。

**发现新侧开口。** 条件是左或右事件为真，并且 `afterDepartForwardMs >= 250`。事件本身还要求连续开口投票达到 3，且该侧没有 latch。

进入时：

1. 把事件抄到候选标志上。左右可以同时为真。
2. 触发的那一侧 latch。
3. `phaseUsesJ3Trim` 先清掉，避免上一次的标志残留。正常情况下 `depart()` 已经清过。
4. 若有左侧候选，时间从 1110 起：
   - `lastPhysicalTurn == 1` 且这条腿短于 2960 ms：加 100。
   - `expectingJ1Return()`：减去 120，并用防下溢函数。
   - `expectingJ3()`：加 180，置 `phaseUsesJ3Trim`。
   - 1 号和 3 号的条件互相排斥：一个要求阶段 0 且正在退回且车头朝右，一个要求阶段 2 且正在探索且车头朝左。不会两个同时加上。
5. 没有左侧候选：时间就是右侧的 1120。右侧单独出现时不加短腿补偿，也不加 START 1 补偿。
6. T 字标志清掉，阶段设为 2，记下开始时刻，85% 开走。

**阶段 1。** 若窗口前向已经是开，并且这一帧原始 `bands < 3`，说明前墙消失了，阶段退回 0，85% 继续开。这能取消一次误触发的接近。

时间到达 1776 ms 时：窗口必须匹配最后一帧，且前向必须是墙。否则故障 5。通过就决策，`safetyStopped` 为假，因为这是按计划开到的，不是贴墙急停。时间未到就继续 85% 开。

**进入阶段 1。** 上面都没发生，而这一帧前方 `bands >= 3`，就把阶段设为 1 并记下时间。这里用的是单帧 `bands`，不是 7 帧窗口。所以前墙接近可以在窗口还没投票完成时就开始。真正转弯仍要等时间走完且窗口有效。

**普通直行。** 100% 纠偏，只亮中间灯。阶段 1 和阶段 2 的分支不会调用 `leds()`，转弯时点亮的左右灯会保持到下一次有人改灯。慢速接近路口期间，灯可能仍是上一次转弯留下的样子。

## 把一次普通探索按时间串起来

从 START 1 朝图左出发，软件侧把一次搜索串成八步。每一步都写了“这一拍谁在干活”，不假设真实路口的厘米数。

1. `setup` 写好哨兵根：只有出发方向算通，而且已经标成走过，没有父边。窗口里只有 1 帧，签名还不成立，所以这一拍不能 DFS。车以 85% 出发。已行驶时间被预先写成 250 ms，第一个侧开口不用再白等重臂时间。
2. 接下来几帧如果没有前墙、也没有侧开口，Moore 机留在阶段 0，速度变成 100%。左右有墙就按第 6 节的五级控制律纠偏。两面都没有墙，误差和修正清零，车按标定脉宽直开。
3. 某一侧连续 3 帧明确开口，且该侧的锁是开的：这是一条新边的起点，但先不搜索。进入阶段 2，开始对中计时。基础时间左侧 1110 ms。若软件状态像“退回 1 号”，减成 990 ms。若像“去 3 号”，加成 1290 ms，并记下这次用了 3 号延后。
4. 阶段 2 期间每帧仍在采样、仍在纠偏。窗口若变成左开、前墙、右开，再加 80 ms，这个加时一旦置位就不取消。时间到了还要再看两件事：候选侧这一帧仍是开口，7 帧签名和最后一帧一致。两件都过，才把签名交给 DFS。有一件不过，就停车重扫，而不是边走边转。
5. 这条腿是探索边，DFS 先 push。来路标成已走，再按左、前、右挑第一条新出边，`depart`。需要转弯就阻塞转到目标航向，航位计时归零，旁边现成的开口被锁住，出发后 250 ms 内的新开口也不承认。
6. 若看到的是前墙而不是侧开口：不立刻搜索。进入阶段 1，慢速再开 1776 ms，给车开到墙前的顶点。中途反射强到 `bands >= 5` 且 `votes >= 14`，说明再开就会顶上，立刻停车重扫再搜索，不再等剩余时间。唯一的例外是 3 号延后还没走完：那时故障 13，不把贴墙当成顶点。
7. 一个顶点的左、前、右都试过之后，下一次转移没有出边，就向父方向出发，`travelKind` 变成 1，栈顶先减 1。开回到上一个顶点时先做签名核对，再在那个旧顶点上选还没走的边。核对失败是故障 8，栈停在那里。
8. 若某次转移时，这条边已经开过 1.5 格，左右夹墙的累计时间超过 3 格，而且签名是三面墙：这是叶边终点，不是一次 pop。三灯常亮，程序结束。

1 号和 3 号只出现在第 3 步的毫秒数里。它们不改第 5 步 DFS 选哪一边，也不改 `turnTo()` 里左转维持的 615 ms。

| 通用输入输出 | general-purpose input/output, GPIO | `pinMode`、`digitalWrite`、`digitalRead` 使用的脚 |
| 模数转换器 | analog-to-digital converter, ADC | A0–A2 具备这个能力；程序只把它们当数字输出点灯 |
| 串行采样 | serial sampling | 前、左、右一个接一个测，不是三路同时亮 |
| 指数滑动平均 | exponential moving average, EMA | `0.2 × 旧误差 + 0.8 × 新误差` |
| 无限脉冲响应 | infinite impulse response, IIR | 滤波输出会回到下一次输入，一次噪声会留下逐渐变小的尾巴 |
| 有限脉冲响应 | finite impulse response, FIR | 7 帧窗口只看固定的最近样本，更接近这种形式 |
| 一阶低通 | first-order low-pass filter | 只有一个记忆单元，放行慢变化、削弱快抖动 |
| 死区 | deadband | 滤波误差在 ±1 以内时，修正命令为 0 |
| 寻迹振荡 | hunting | 在设定值附近来回修 |
| 比例控制 | proportional control | 命令 = 增益 × 误差 |
| 比例增益 | proportional gain, Kp | 这里是 `CORRECTION_GAIN = 4` |
| PID | proportional-integral-derivative | 比例、积分、微分。这份程序只有比例 |
| 积分 / 稳态误差 / 积分饱和 | integral / steady-state error / integral windup | 代码里没有积分项，因此也不处理这三件事 |
| 微分 | derivative | 代码里没有。它本来按误差变化的快慢提前加减命令 |
| 超调 | overshoot | 增益过大时修过了头。变化率限制用来减轻突然的命令 |
| 变化率限制 | slew-rate limit | 每帧修正量最多比上一帧变化 6 µs |
| 限幅 | saturation, clamping | 修正被限制在 ±20 或 ±22 µs，并且小于前进偏移 |
| 整数除法 | integer division | `58 × 85 / 100` 得到 49，小数部分被丢掉 |
| 锁存器 | latch | `leftLatched`：开口处理过之后保持为真 |
| 置位 / 复位 | set / reset | 发现开口时置位；连续 3 帧墙时复位 |
| 重新武装 | re-arm | 复位之后，下一扇开口才允许再次触发 |
| 环形缓冲 | ring buffer, circular buffer | `scanWindow[7][3]`，写到末尾就覆盖最旧一帧 |
| 由时间导出的状态 | time-derived state | 故障灯的亮灭由 `millis() % 周期` 算出，不另存闪烁次数 |
