## 🔵 Q9 / Q10 — 数据通路看图识指令

**只盯红线"终点"+ 图上标注词，1 秒出答案**

| 图上标注词 | 数据在哪 | → 往哪送 | 答案 |
|---|---|---|---|
| **"value in register"** | 寄存器里 | 送去存储器 | **ST** |
| **"value in address / memory"** | 存储器里 | 送去寄存器 | **LD** |
| 两寄存器经 ALU 直连、不碰存储器 | 寄存器→寄存器 | — | **MOV** |

**判断树：**
```
红线终点是存储器？ ──是→ ST
      │否
数据来自存储器？ ──是→ LD
      │否（来自寄存器）
      → MOV
```

⚠️ **Indirect / Direct 只是寻址方式**，不改大类 → 只决定加不加 S（LDS / STS）。别被干扰。

## 🟢 Q5 / Q6 — 打擂台 vs 累加卡上限

### 怎么区分（命中一条即定案）
```
.data 有数组 + 循环里有 ld r?,X+ ?
     │是 → Q5（打擂台）
     │否（全是寄存器互算）→ Q6（累加）
```
再确认：**Q6 循环开头 = add 后 cpi 常数(上限) + 第二个 cpi 0**

### Q5 打擂台（求 max / min）
核心两行 `cp 新,擂主` + `br?? 跳过更新`：

| 分支 | 留下的是 |
|---|---|
| **`brlo`**（小就跳过）| **MAX** |
| **`brsh`**（大就跳过）| **MIN** |

> 口诀：**跳过小的留大的(max)，跳过大的留小的(min)**
> ✅ 答案一定是**数组里的某个元素**

### Q6 累加卡上限
逐轮画 **(r16, r17)** 表，每轮：
1. 算 `r18 = r16 + r17`，≥ 上限 → 停
2. `dec r17`，`r16 += r17`

> ✅ 答案是个**和**，比任何输入都大、数组里没有

## 🟡 Q7 / Q8 — 栈指针 & 递归深度

### Q7 栈指针位移（算净 Δ，不画栈）

| 操作 | ΔSP |
|---|---|
| push | **−1** |
| pop | **+1** |
| call | **−2** |
| ret | **+2** |
| 中断触发 | **−2** |
| reti | **+2** |

**秒算技巧：**
- push/pop 先抵消，剩几个 push = −几
- **call 和 ret 配对相消**（数量相等直接归零！）
- 中断/reti 同理配对相消

$$\Delta = -(push) + (pop) - 2(call) + 2(ret)$$

⚠️ 别忘了**题目初值和答案都要按进制转**（hex↔dec）

### Q8 递归栈深度

**每次调用占用 = 返回地址 2 字节 + 参数个数 × 1 字节**

$$次数 = \left\lfloor \frac{栈总大小}{2 + 参数数} \right\rfloor \quad(\text{向下取整})$$

> 例：3 参数 → 每次 5 字节；415 ÷ 5 = **83**
> 除不尽**一律向下取整**（余下不够完整一次调用不算）

## ⚡ 全局提醒（最容易丢分的坑）

1. **分支方向**：`brlo`=C置位(更小)跳 / `brsh`=C清零(≥)跳 / `brne`=不等跳 / `breq`=相等跳
2. **跳转后 X 指针位置变了** → 后面 `ld X+` 读到的元素跟着错位（Q2 类）
3. **`lsl`=×2，`lsr`=÷2，`inc`=+1，`subi r,k`=r−k**
4. **跳转后那段代码可能是死代码**，别去算它
5. **进制**：栈题常给 hex、要求 dec 作答（或反之），看清再写




# 三步法：先看**亮到哪个方块**，再看**方向**，最后看**地址线**

不要从指令名去反推图，要反过来：**从红线的两个端点直接读出答案**。

---

## 第一步：红线有没有离开「ALU + 寄存器堆」这一团？

| 观察 | 结论 |
|---|---|
| 红圈只在这一团里，8 位数据总线、Data Memory、Program Memory 全黑 | **纯寄存器运算**：ADD/SUB/AND/OR/EOR/MOV/MUL/CP/CPC 等 |
| 红线穿过中间的 **8 位数据总线**，并连到外面的大方块 | 去第二步 |

这一步能自动排除掉一半选项。**总线上没有红线，就不可能是 load、store、IN/OUT、LPM**。

---

## 第二步：总线另一头接的是哪个方块？

| 总线连到的方块 | 数据往寄存器方向 | 数据往方块方向 |
|---|---|---|
| **Data Memory** | **LD**、LDS、LDD、POP | **ST**、STS、STD、PUSH |
| **Program Memory** | **LPM**（还有 ELPM） | **SPM** |
| **I/O Modules**（Module 1/2…） | **IN** | **OUT** |
| 什么都没连，只连 Decoder | 立即数类：LDI、ANDI、SUBI… | — |

三个内存方块彼此离得很远，一眼就能分清，这一步最省时间。

---

## 第三步：地址那根线走的是哪条？

只有需要访存时才看：

- 从**左边 Decoder / Instruction Register 拉出的长横线**，标注在 **Direct Addressing** 上 → 地址嵌在指令里 → **多一个 S**（LDS、STS）
- 从**寄存器堆右下角 R26–R31 那小块**引出，经 **`@`** 进 Data Memory → 地址来自 X/Y/Z 指针 → **短名**（LD、ST）
- 如果图上还画了 **q（位移量）** 加进地址计算 → 再多一个 **D**（LDD、STD）

---

## 字母数不是随便给的，它编码的是**寻址方式**

| 后缀 | 含义 |
|---|---|
| **S** | 16 位直接地址（Direct Addressing 那根线） |
| **D** | 带位移量 q（Indirect + q） |
| **I** | 立即数（第二输入来自 Decoder） |

所以看到题目写“2 or 3 letter”，基本就是在提示你：**先判断寻址方式，再判断操作**。操作名（L、ST、AND…）从数据方向读，后缀从地址线读，两件事分开判断，不要混着看。

---

## 三个 3 秒钟自查

**① 写回端有没有红线？**
- 有 → 结果要落回 Rd
- 没有，只有 SREG 亮 → 比较/测试类：**CP、CPC、TST、CPI**
- 注意 LDI 没有读端口，只有写端口

**② 寄存器堆两个读端口都亮吗？**
- 两个都亮 → 两个寄存器操作数（ADD Rd,Rr）
- 只有一个亮 → 另一操作数是立即数（从 Decoder 来）或单操作数指令（INC/DEC/COM）

**③ 方向看箭头，不看谁被点亮**
- 图上 `value in address` 那个箭头指向寄存器堆 → **写回寄存器**
- 同一条通路箭头反向 → **store**
4 和 5 两道题唯一的差别就是这一点，别被“地址线一样”骗了。

---

**一句话口诀：**

> 看总线通到哪个内存方块，定指令族；看数据箭头的方向，定 load 还是 store；看地址线来自 Decoder 还是 R26–R31，定有几个字母。
